In this document, the full complement of NS32CG16 new instructions are
detailed, and emulated. The emulations are exact, so far as to produce the
same results as the microcode should, with the same input parameters.

Some differences should be noted, however.

Some instructions (like TBITS) use immediate values encoded into the
instruction for some parameters. Where appropriate, the 32000 emulation
code uses two (or more) routines to simulate this. For example, the TBITS S
instruction is simulated with a BSR TBITSS.

As well, the PSR register values for certain instructions may be altered by
the emulation code, but not by the microcode. The exit conditions
documented for the instructions are accurate, however.

In all, these emulations should be treated as Functional Equivalents for
the microcode. All input values in registers, and output values in
registers and memory should be the same for both the microcode and the
32000 code.

The 32032 timings were done on a 0 wait state 32032 system, with 2
megabytes of DRAM. The 32016 timings were done on a 0 wait state 32016
system with a MMU, and 2 megabytes of DRAM.

All NS32CG16 instruction timings are ESTIMATED.

BITWT Emulation code


The BITWT instruction allows a very fast logical OR-with-shift. This
instruction can be used as the inner loop of a BITBLT s OR d operation,
with no masks.

BITWT (Bit Aligned Word Transfer)

R0 Source pointer
R1 Destination pointer
R2 Shift value ( If > 32, source becomes zero)
( If > 16, some source bits are lost)

        movd        tos,r3                ;get back our register

Note that the movd r3,tos and movd tos,r3 instructions are used to obtain a
working register for the algorithm. In microcode, this is not required. As
well, if a number of BITWT instructions are 'in line', as is normally the
case, the saving of r3 can be done at the start of the group. The restore
can be done at the bottom of the group. This prevents the extra overhead
between each instruction simulation.
BitBlt Series


The BITBLT (Bit Aligned Block Transfer) group of instructions require a
preprocessor to obtain the masks and shift values from the more common
inputs (i.e. source address/bit offset, destination address/bit offset).
Below is an example of a preprocessor for the internal BitBlt instructions.

        .data
        .align        4
masks:        .word        0xffff,0xfffe,0xfffc,0xfff8,0xfff0
        .word               0xffe0,0xffc0,0xff80,0xff00
        .word               0xfe00,0xfc00,0xf800,0xf000
        .word               0xe000,0xc000,0x8000,0x0000

        .text

#        BitBlt preprocessor
#        Inputs:
#                r0 = Source byte address
#                r1 = Destination byte address
#                r2 = width of image in bits
#                r3 = height of image in bits
#                r4 = source bit offset
#                r5 = destination bit offset
#                r6 = source warp in bytes
#                r7 = destination warp in bytes
#        Outputs:
#                r0 = source address
#                r1 = destination address
#                r2 = shift value
#                r3 = height in lines (word quantity)
#                r4 = first mask
#                r5 = second mask
#                r6 = adjusted source warp 
#                r7 = adjusted destination warp
#              0(sp)= width in words (word quantity)

pre:        movd        r2,tos                #save current width on stack
        movd        r3,tos                #save height on stack, free r3

        movd        r4,r3                #make a copy of starting bit off
        ashd        $-4,r4                #divide source bit offset by 16
        addd        r4,r0                #add word offset to source address
        addd        r4,r0

        addr        15,r2                #we only want last 4 bits of
        andd        r5,r2                #the destination x value

        ashd        $-4,r5                #divide by 16 to get word offset
        addd        r5,r1                #add offset to destination addr.
        addd        r5,r1

        movd        r3,r5                #get source bit offset
        addd        4(sp),r5        #add in width of image
        addqd        -1,r5                #and subtract one
        andd        $15,r5                #mask all but 4 lsb's
        comw        masks+2[r5:w],r5#and get rmask value

        addr        15,r4                #store mask for index into lmasks
        andd        r3,r4                #get 4 lsb's of src bit position
        subd        r4,r2                #subtract src offset from dst to get
                                #shift amount
        addr        16,r3                #calculate start bit
        subd        r4,r3                #hold start bit (16-0) in r3
        movw        masks[r4:w],r4        #get lmask value

        movd        r2,tos                #get a free register
        movd        8(sp),r2        #get width
        cmpd        r3,r2                #is w < start bits?
        ble        pre1                #no, multi-word blit, else
        andd        r5,r4                #merge the two masks
        movqd        1,r2                #and set the width to one
        br        pre1a

        .align        4
pre1:        subd        r3,r2                #width = (wbits - startbit - 1)/16 +2
        addqd        -1,r2
        ashd        $-4,r2                #width /= 16
        addqd        2,r2                #and add two

pre1a:        movd        r2,8(sp)        #store width away
        addqd   -1,r2           #adj.warp = (warp - (width - 1) * 2)
        subd        r2,r7                #and subtract width from dwarp
        subd        r2,r7                #(width is in words, warp in bytes)
        subd        r2,r6                #and swarp
        subd        r2,r6                #see above
        movd        tos,r2                #get back our shift amount

        cmpqd        0,r2                #is shift negative?
        blt        pre2a                #yes, it is negative
pre2:        addd        $16,r2                #we need a bit more shift
        addqd        -2,r1                #and to back up destination

        .align        4
pre2a:        movd        tos,r3                #get back height
#
#        Execute BitBlt function here
#
        cmpqd        0,tos                        #unstack width
        ret        0                        #and return
This code requires 400-500 clocks, depending on input values and processor.
This preprocessor assumes that the direction is always visual left to right
and top to bottom (increasing bit/byte direction). It correctly identifies
the cases where the destination pointer needs to be predecremented, and
handles the special one-word-wide case.

This code sets up all data for the BBFOR, BBOR and BBXOR functions. Two
additional instructions are required for the BBAND function, and may be
place following the label 'pre2a' in the listing.

          comw      r4,r4          # Complement first mask
          comw      r5,r5          # Complement second mask
This correctly sets up the masks for the BBAND function, in 22 clocks.

Since the preprocessor is much the same for all internal BitBlt functions,
one subroutine will serve all. A CASE instruction may be used to jump to
the correct routine. Alternatively, separate preprocessor may be used for
each BitBlt function for maximum speed. Using a pre-calculated address, the
CASE instruction adds 29 clocks.

The NS32CG16 uses a technique called 'Source Masking', and thus the
preprocessor may be unfamiliar to those used to working with more
conventional BitBlt software/hardware.

The NS32CG16 Application notes will feature a more general purpose BitBlt
preprocessor, capable of automatic determination of direction.
External BitBlt Preprocessor

Since the EXTBLT instruction communicates with the DP8510/DP8511, a
different preprocessor is required. The DP8510/DP8511 use the technique
called 'Destination Masking', and the masks are therefore calculated
differently. Below is an example of the EXTBLT preprocessor.


#        External BitBlt preprocessor
#        Inputs:
#                r0 = Source byte address
#                r1 = Destination byte address
#                r2 = width of image in bits
#                r3 = height of image in bits
#                r4 = source bit offset
#                r5 = destination bit offset
#                r6 = source warp in bytes
#                r7 = destination warp in bytes
#        Outputs:
#                r0 = source address
#                r1 = destination address
#                r2 = current preload indicator
#                r3 = current width
#                r4 = actual preload indicator
#                r5 = actual width
#                r6 = adjusted source warp 
#                r7 = adjusted destination warp
#              0(sp)= height in lines (word quantity)

epre:        movd        r3,tos                #save height on stack, free r3
        movd        r2,tos                #save width on stack, free r2

        movd        r4,r3                #make a copy of starting bit off
        ashd        $-4,r4                #divide source bit offset by 16
        addd        r4,r0                #add word offset to source address
        addd        r4,r0

        addr        15,r2                #we only want last 4 bits of
        andd        r2,r3                #the source x value, and
        andd        r5,r2                #the destination x value
        subd        r3,r2                #shift = (dx - sx)
        andd        $15,r2                #mask back to 0-15
        movqd        0,r4                #assume no preload
        cmpqw        0,r2                #was there any shift?
        beq        epre0:b                #no, skip it.
        cmpw        r2,r3                #is the shift less than the bit off?
        bgt        epre0:b                #no... skip it
        addqd        -2,r6                #pre-decrement source warp to show
        movqd        1,r4                #preload in effect

epre0:        lshd        $8,r2                #and shift it left 8 bits to
                                #align with control register
        
        movd        r5,r3                #make a copy of destination x
        ashd        $-4,r5                #divide by 16 to get word offset
        addd        r5,r1                #add offset to destination addr.

        addd        r5,r1
        movd        r3,r5                #get back destination x
        addd        0(sp),r3        #add in width of image
        addqd        -1,r3                #and subtract one
        andd        $15,r3                #mask all but 4 lsb's
        movb        r3,r2                #move into position for control reg.

        andd        $15,r5                #mask to get starting x value
        movd        r5,r3                #save this value for starting bit
        lshd        $4,r5                #shift to align with control reg.
        orw        r5,r2                #and or it in.
        addr        16,r5                #calculate start bit
        subd        r3,r5                #hold start bit (16-0) in r5

        movd        0(sp),r3        #get width
        cmpd        r5,r3                #is w < start bits?
        ble        epre1:b                #no, multi-word blit, else
        movqd        1,r3                #set the width to one
        br        epre1a:b

        .align        4
epre1:        subd        r5,r3                #width = (wbits - startbit - 1)/16 +2
        addqd        -1,r3
        ashd        $-4,r3                #width /= 16
        addqd        2,r3                #and add two

epre1a:
        subd        r3,r7                #and subtract width from dwarp
        subd        r3,r7                #(width is in words, warp in bytes)
        subd        r3,r6                #and swarp
        subd        r3,r6                #see above


        .align        4
epre2a:        cmpqd        0,tos                #unstack width (now in r3)
        movd        r3,r5                #save width in r5

epre3:        movd        r4,r2                #get preload indicator
        movd        r5,r3                #get width in words
#
#      EXTBLT instruction goes here
#
        addd        r6,r0                #add source warp
        addd        r7,r1                #add destination warp
        acbw        -1,tos,epre3        #and loop until done
        cmpqd        0,tos                #unstack height
        ret        0

This code requires about 400 clocks to do the preprocessing, and about 41
clocks per line of overhead for the loop starting at the label 'epre3:'.
This can be unrolled, if the height is constant.
BitBlt Emulation

The four primary BitBlt instructions (BBOR, BBAND, BBFOR and BBXOR) are
somewhat difficult to emulate, since some of the the values are immediate
(such as IS). Two methods of emulation are therefore presented. The first
is a general purpose BITBLT. Along with the width at 0(sp), the general
purpose BITBLT expects a function word at 2(sp) prior to the BSR to enter
this function. The function word is defined in the listing below. Note that
0(sp) becomes 4(sp) due to the BSR to enter this function.

#Emulations of BBOR BBAND BBXOR and BBFOR
#
#        Inputs:
#                r0 = source address
#                r1 = destination address
#                r2 = shift value
#                r3 = height in lines (word quantity)
#                r4 = first mask
#                r5 = second mask
#                r6 = source warp
#                r7 = destination warp
#              4(sp)= width in words (word quantity)
#
#              6(sp)= Function/direction (immediate in microcode)
#                     bit 1 0
#                         0 0        AND
#                         0 1        OR
#                         1 0        XOR
#                         1 1        FOR
#                     bit 2 = NOT source
#                     bit 3 = RD (Reverse Direction)
#
#        Ouputs:
#                all registers destroyed.
#                Data in memory changed.
#        
        .align        4
bbgen:        movd        r3,tos                #save height, free r3
        movd        r6,tos                #save source warp, free r6
        movd        r7,tos                #save destination warp, free r7
        movqd        3,r7                #place mask in r7
        andd        18(sp),r7        #get function code
        addr        r7[r7:q],r7        #r7 *= 9
        addr        andmfnc:w[r7:d],tos #figure address (each func is 36 bytes)
#
#Now register map looks like:
#
#                r0 = source address
#                r1 = destination address
#                r2 = shift value
#                r3 = temporary register for blt work
#                r4 = first mask
#                r5 = second mask
#                r6 = horizontal increment
#                r7 = current width
#             21(sp)= width in words (word quantity)
#
#             23(sp)= Function/direction (immediate in microcode)
#
#              0(sp)= flags via SPRB upsr
#              1(sp)= src to destination routine address
#              5(sp)= destination warp
#              9(sp)= source warp
#             13(sp)= height        (word quantity)
#             

        movb        22(sp),r7        #get function byte

        tbitb        2,r7                #set flags for inversion of source
        cmpqb        0,0                #assume no inversion
        bfc        bbg1a:b                #yes, no inversion
        cmpqb        1,0                #please invert source
bbg1a:        sprb        upsr,tos        #save inversion status in the Z flag

        movqd        2,r6                #assume incrementing direction
        tbitb        3,r7                #is it?
        bfc        bbgen1:b        #it is.
        movqd        -2,r6                #it is decrementing direction
bbgen1:
        movw        21(sp),r7        #get current width
bbgen1a:
        lprb        upsr,0(sp)        #get back Z flag
        jsr        0(1(sp))        #do function
        addqd        -2,r7                #width -= 2
        cmpqd        0,r7                #if width is now zero, do other mask
        beq        bbgenmsk2:b        #yes, do other mask
        bgt        bbgenend:b        #if width is < zero, line is done

        lprb        upsr,0(sp)        #get back Z flag
        .align        4
bbgen2:        jsr        14(1(sp))        #do function
        acbd        -1,r7,bbgen2        #and loop for all inner words
        
bbgenmsk2:
        lprb        upsr,0(sp)        #get back Z flag
        movd        r4,r7                #copy left mask to temp
        movd        r5,r4                #use right mask now
        jsr        0(1(sp))        #do function
        movd        r7,r4                #get back left mask
bbgenend:
        addd        9(sp),r0        #add source warp
        addd        5(sp),r1        #add destination warp
        acbw        -1,13(sp),bbgen1#and loop for entire blt

        adjspb        $-17                #unstack all items
        ret        0                #and return


        .align        4
andmfnc:
        movqd        -1,r3                #fill upper bits with 1's
        movw        0(r0),r3        #get word
        beq        andf1:b                #if no inversion, skip
        comw        r3,r3                #inversion of source
andf1:        orw        r4,r3                #do mask
        br        andf2:b                #rejoin code

andfunc:
        movqd        -1,r3                #fill upper bits with 1's
        movw        0(r0),r3        #get word
        beq        andf2:b                #if no inversion, skip

andf2:        rotd        r2,r3                #rotate to align
        andd        r3,0(r1)        #and to destination

        addd        r6,r1                #to source and destination
        ret        0                #and return


        .align        4

        comw        r3,r3                #inversion of source

#Emulations of BBOR
#
#        Inputs:
#                r0 = source address
#                r1 = destination address
#                r2 = shift value
#                r3 = height in lines (word quantity)
#                r4 = first mask
#                r5 = second mask
#                r6 = source warp
#                r7 = destination warp
#              0(sp)= width in words (word quantity)
#
#              2(sp)= Function/direction (immediate in microcode)
#                     bit 0 = NOT source
#                     bit 1 = RD (Reverse Direction)
#
#        Ouputs:
#                all registers destroyed.
#                Data in memory changed.
#        

bbor:
        movd        r3,tos                #save height, free r3
        movd        r6,tos                #save source warp, free r6
        movd        r7,tos                #save destination warp, free r7

#
#Now register map looks like:
#
#                r0 = source address
#                r1 = destination address
#                r2 = shift value
#                r3 = temporary register for blt work
#                r4 = first mask
#                r5 = second mask
#                r6 = horizontal increment
#                r7 = current width
#             12(sp)= width in words (word quantity)
#
#             14(sp)= Function/direction (immediate in microcode)
#
#              0(sp)= destination warp
#              4(sp)= source warp
#              8(sp)= height        (word quantity)
#             
        movqd        2,r6                #assume incrementing direction
        tbitb        1,14(sp)        #is it?
        bfc        bbor1:b                #it is.
        movqd        -2,r6                #it is decrementing direction
bbor1:        movw        12(sp),r7        #get current width

        movzwd        0(r0),r3        #get first word in line
        tbitb        0,14(sp)        #do invert source?

        comw        r3,r3                #else invert the source
bbor1a:        andw        r4,r3                #mask the source
        rotd        r2,r3                #shift left to align
        ord        r3,0(r1)        #or to destination
        addd        r6,r0                #add in horizontal increment
        addd        r6,r1                #to source and destination
        addqd        -2,r7                #width -= 2
        cmpqd        0,r7                #if width is now zero, do other mask
        beq        bbormsk2:b        #yes, do other mask
        bgt        bborend:w        #if width is < zero, line is done

        tbitb        0,14(sp)        #set flags for inversion of source
        cmpqb        0,0                #assume no inversion
        bfc        bbor2:b                #yes, no inversion
        cmpqb        1,0                #please invert source

        .align        4
bbor2:        movzwd        0(r0),r3        #get next word
        beq        bbor2a:b        #if Z flag set, no inversion
        comw        r3,r3
bbor2a:        rotd        r2,r3                #shift to align
        ord        r3,0(r1)        #and or to destination
        addd        r6,r0                #add in horizontal increment
        addd        r6,r1                #to source and destination
        acbd        -1,r7,bbor2        #and loop for all inner words

bbormsk2:
        movzwd        0(r0),r3        #get last word
        tbitb        0,14(sp)        #do invert source?
        bfc        bbor3a:b        #no, no inversion
        comw        r3,r3                #else invert the source
bbor3a:        andw        r5,r3                #do second mask
        lshd        r2,r3                #shift to align
        ord        r3,0(r1)        #or to destination
        addd        r6,r0                #add horizontal increment
        addd        r6,r1                #to source and destination

bborend:addd        4(sp),r0        #add source warp
        addd        0(sp),r1        #add destination warp
        acbw        -1,8(sp),bbor1        #and loop for entire blt

External BitBlt

With the external BITBLT, exact emulation is impossible, since the hardware
signals do not exist on the 32000 series. Simulation via a hardware
register is possible, however, and is reproduced below.


#Emulations of EXTBLT
#
#        Inputs:
#                r0 = source address
#                r1 = destination address
#                r2 = number of source reads
#                r3 = width in words
#
#        Ouputs:
#                r0, r1 set to the next transfer address
#                r3 is modified. r2 is altered
#                Data in memory changed.
#        
        .data
        .align        4
masks:        .word        0                #mask enables
nme:        equ        0                #no masks on
lme:        equ        1                #left mask on
rme:        equ        2                #right mask on

        .text
extblt:
        tbitb        1,r2                #do we increment or decrement
        bfs        ext2:b                #we decrement
        tbitb        0,r2                #two source reads?
        bfc        ext1a:b                #no, just one
        movw        0(r0),r2        #do a pre-read
        addqd        2,r0                #increment source address
ext1a:        movqw        lme,masks        #turn on left mask
        addqd        -2,r3                #how many left?
        cmpqd        0,r3                #was it a one word wide?
        bgt        ext1b:b                #yes, do right mask too
        orw        0(r0),0(r1)        #do read/read-modify-write
        addqd        2,r0                #increment source address
        addqd        2,r1                #increment destination address
        beq        ext1c:b                #it was two words wide
        movqw        nme,masks        #no masks now
ext1d:        orw        0(r0),0(r1)        #do read/read-modify-write
        addqd        2,r0                #increment source address
        addqd        2,r1                #increment destination address
        acbd        -1,r3,ext1a        #and loop until done
ext1c:        movqw        rme,masks        #turn on right mask
ext1e:        orw        0(r0),0(r1)        #do last read/read-modify-write
        addqd        2,r0                #increment source address
        addqd        2,r1                #increment destination address
        ret        0                #we are done


ext1b:        movqw        lme+rme,masks        #turn on both masks
        br        ext1e                #and do the read/read-modify-write

ext2:        tbitb        0,r2                #two source reads?
        bfc        ext2a:b                #no, just one
        movw        0(r0),r2        #do a pre-read

SBITS instruction definition

The SBITS instruction is typically used to set a number of bits in a block
of memory to '1'. In order to make this instruction as fast as possible, it
uses a 1024 byte external table. This table is defined at the end of this
document. The formal definition of the SBITS instruction is:

SBITS (Set Bit String)

R0 Base address
R1 Bit offset
R2 Run length
R3 Address of SBITS table


Note that SBITS may safely be called with a run length of zero. This
simplifies boundary conditions. SBITS may only be used in the horizontal
(bit offset increasing) direction. The SBITPS instruction can be used with
a register supplying the bit increment value, allowing perpendicular lines
to be drawn as well.

SBITS first compares the run length with 25. If the length is greater than
25, SBITS sets the F flag and exits. This allows the external software to
use a more efficient algorithm to set large quantities of bits. If your
application only requires 1-24 bits, no external software is required to
use this instruction. if the run length is less than or equal to 24, SBITS
clears the F flag.

SBITS then calculates the starting base address from the base address
supplied, and the bit offset, according to the following formula.

base address = base address + (bit offset DIV 8)
bit offset = (bit offset MOD 8)




The actual 32000 code representation of this is:

     movd  r1,temp       ;save the bit offset for a second
     ashd  -3,r1         ;divide the bit offset by 8, signed
     addd  r1,r0         ;r0 = r0 + (r3 / 8)
     movqd 7,r1          ;place a mask in r1
     andd  temp,r1       ;r1 = (bit offset .and. 7)

This adjusts the base pointer to the nearest byte of the data to be
affected. The bit offset will always, therefore, be in the range 0 to 7.

Assuming the run length is 24 or less, SBITS then indexes into the table
according to the following equation:

index = table address + 4 * (run length + (32 * bit offset))

Since the bit offset has been previously adjusted to the range 0 to 7, only
a 1024 byte table is required (8 rows of 128 bytes).


The actual 32000 code representation of this would be:

     movd  r1,temp            ;store bit offset to temp
     lshd  5,temp             ; temp = (32 * bit offset)
     addd  r2,temp            ;temp = temp + run length
     lshd  2,temp             ;temp = temp * 4   
     addd  r3,temp            ;index = base of table + offset

SBITS then does a logical OR to move the specified bits into position, from
the table to the destination address.

The 32000 code representation of this would be:

     ORD  0(temp),0(r0)       ;Set the required bits

Again, note that while no special test is made for a run length of zero, no
harm will occur to the destination data since the table contains all zeros
at a run length of 0.

If the run length is greater than 24 bits, an external software algorithm
should be used. This increases the speed even more. A sample software
algorithm incorporating the MOVMP instruction is reproduced on the
following page.

TBITS Emulation code

The TBITS instruction is generally used for RLL (Run Length Limited)
compression, although it can also be used to find boundaries in graphics
patterns. Below are some examples of RLL compression algorithms implemented
using the TBITS instruction.

TBITS 0 | 1 (Test Bit String)

R0 Source base address
R1 Source bit offset
R2 Destination RLL code
R3 Maximum value RLL code
R4 Maximum source bit offset

R1 and R2 are modified by this instruction. All other registers are
preserved.

There are two possible operations for TBITS: count zeros, and count ones.
TBITS 0 scans for zeros starting at the source bit offset, and stops when
it finds a one bit. TBITS 1 scans for ones, and stops when it finds a zero
bit. Other exit conditions are possible, as is shown below:

Flags
Condition Z N L F Notes
R2 < R3, bit found 1 0 0 F F reflects last bit tested
R2 => R3, not found 1 0 0 F F reflects last bit tested
R1 => R4, not found 0 1 1 F F reflects last bit tested
R1 => R4 on entry 0 1 1 0/1 F = n (TBITS n)

The last entry in the table is for the case of the starting bit offset
already larger than the maximum bit offset. In this case, R2 is zeroed, and
the F flag is set to the condition the instruction was testing for.

        addqd        1,r2                ;add one to run length

        blt        tbitzero        ;no, keep looking

        ret        0

        ret        0                ;and we are done

Encoding techniques

There are several encoding techniques using RLL: Alternating 0/1, embedded
control, variable length and Huffman post-processing are a few of them.
Three techniques are presented on the following pages, including
Alternating 0/1, embedded control, and an optimized embedded control with
no run lengths of zero. The best RLL encoding technique is totally
dependent on the data set involved. Each of these routines (using the 32000
emulation code) take about 22 msec to compress a 32 by 32 font. 

;Comp1 does an alternating 0/1 compression, with a fixed 3 bit
;run length (0 to 7 as the run). The data to be compressed is
;an 32 by 32 font matrix, initialy aligned on a byte boundary (byte
;alignment is not required.
;Comp1 uses the insb instruction to insert the 3 bits of RLL code
;into an output buffer.
;The actual routine set-up is from label comp1 to label reline.
;        Registers used:
;                r0 = source base address
;                r1 = source starting bit offset
;                r2 = working run length
;                r3 = maximum run length
;                r4 = maximum bit offset (source)
;                r5 = address of destination buffer
;                r6 = bit offset of destination buffer
;                r7 = scan line count 
comp1:        
        addrd        mess,r0                ;point to base
        movqd        7,r3                ;max run length is 3 bits
        movd        32,r4                ;maximum bit offset
        addrd        buf,r5                ;destination buffer
        movqd        0,r6                ;starting bit offset
        movd        32,r7                ;line count
reline:        movqd        0,r1                ;starting bit offset
lp2:        TBITS        1                ;look for a zero
        insb        r6,r2,0(r5),3        ;put them bits in
        addqd        3,r6                ;increment bit offset for destination
        bhi        limit1                ;we hit the limit
lp3:        TBITS        0                ;look for a one
        insb        r6,r2,0(r5),3        ;put them bits in
        addqd        3,r6                ;increment bit offset for destination
        ble        lp2                ;if less than the limit, back for more
limit1:        
        addqd        4,r0                ;next line now
        acbd        -1,r7,reline        ;decrement, and loop if more lines
        ret        0               ;amd we are done 

;
;Comp2 does a fixed length RLL code with embedded 0/1 information.
;The run length is 5 bits, with one bit being the 0/1 flag.
;This gives a maximum run length of 15. We are compressing a
;32 by 32 font. Comp2 assumes that all lines begin with zeros.
;
;
;        Registers used:
;                r0 = source base address
;                r1 = source starting bit offset
;                r2 = working run length
;                r3 = maximum run length
;                r4 = maximum bit offset (source)
;                r5 = address of destination buffer
;                r6 = bit offset of destination buffer
;                r7 = scan line count 
;
comp2:
        addrd        mess,r0                ;point to base
        movd        15,r3                ;max run length is 4 bits
        movd        32,r4                ;maximum bit offset
        addrd        buf,r5                ;destination buffer
        movqd        -5,r6                ;starting bit offset (we add 5)
        movd        32,r7                ;line count
reln2:        movqd        0,r1                ;starting bit offset
zero:        addqd        5,r6                ;incr. dest. bit offset
        TBITS        0                ;look for a one
        insb        r6,r2,0(r5),5        ;put them bits in
        bhi        limit2                ;if over limit, deal with it.
        bfc        zero                ;if still clear, back for more
one:        addqd        5,r6                ;increment dest. bit offset
        TBITS        1                ;look for a zero
        orb        h'10,r2                ;set the '1s' flag
        insb        r6,r2,0(r5),5        ;put them bits in
        bhi        limit2                ;if over limit, deal with it.
        bfs        one                ;if still one, look for a one
        br        zero                ;else look at zeros again

limit2:        addqd        4,r0                ;move to start of next line
        acbd        -1,r7,reln2        ;check and loop if more lines
;        addqd        5,r6                ;optional incr. of dest. bit. off.
        ret        0                ;else we are done

;
;Comp3 does a fixed length RLL code with embedded 0/1 information.
;Comp2 does not depend on the first part of a scan line begin zero, and
;auto-determines the optimal code. The resultant file can still be
;decompressed with UNCOMP2. This is a 32x32 font.
;
;
;        Registers used:
;                r0 = source base address
;                r1 = source starting bit offset
;                r2 = working run length
;                r3 = maximum run length
;                r4 = maximum bit offset (source)
;                r5 = address of destination buffer
;                r6 = bit offset of destination buffer
;                r7 = scan line count 
;
comp3:
        addrd        mess,r0                ;point to base
        movd        15,r3                ;max run length is 4 bits
        movd        32,r4                ;maximum bit offset
        addrd        buf,r5                ;destination buffer
        movqd        -5,r6                ;dest. starting bit offset
        movd        32,r7                ;line count
reln3:        movqd        0,r1                ;starting bit offset
zero3:        addqd        5,r6                ;increment dest. bit offset
        TBITS        0                ;check for a one
        insb        r6,r2,0(r5),5        ;put them bits in
        bhi        limit3                ;if over limit, deal with it.
        bfc        zero3                ;if still clear, back for more
        cmpqd        0,r2                ;was rll code a zero?
        beq        one3a                ;yes! skip increment and overwrite 0
one3:        addqd        5,r6                ;increment dest. bit offset
one3a:        TBITS        1                ;look for a zero
        orb        h'10,r2                ;set the '1s' flag
        insb        r6,r2,0(r5),5        ;put them bits in
        bhi        limit3                ;if over limit, deal with it.
        bfs        one3                ;if still one, look for a one
        cmpqd        0,r2                ;was last rll code a zero?
        bne        zero3                ;no. look at zeros again
        addqd        -5,r6                ;it was. overwrite the 0
        br        zero3                ;and look at zeros again

limit3:        addqd        4,r0                ;move to start of next line
        acbd        -1,r7,reln3        ;check and loop if more lines
;        addqd        5,r6                ;optional incr. of dest. bit. off.
        ret        0                ;else we are done
Rotate font emulation
ROTIMG

The new rotate image algorithm (developed by the Electronic Imaging Group
at National Semiconductor) does a very fast 8 by 8 (64 bit) rotation of a
font data. Note also that this algorithm does not exclusively deal with
fonts, but any 64 bit image.

ROTIMG (Rotate Image)

Inputs:
R0 = Source character address
R1 = Source character warp
R4 = Rotate table address

Outputs:
R2 = Destination character low 4 bytes (lsb->msb, 0 - 3)
R3 = Destination character high 4 bytes (lsb->msb, 4 - 7)



The source data is pointed to by R0 on entry. A 'source warp' is contained
in R1. This 'source warp' is added to R0 after each read of the source
data. This allows the rotation of 16 by 16, 32 by 32 and larger fonts. By
way of an example, let's rotate an 8 x 8 character.

ROTIMG deals with the 8 by 8 destination character as 8
sequential bytes in two registers (R2 and R3), as follows:

ROTIMG uses an external table (address in R4) to speed the rotation, and to
limit the amount of code used. This table consists of 256 64 bit entries,
or a total of 2,048 bytes. The table may be located code (PC) or data (SB)
relative. The complete table is at the end of this document.

To rotate the character, the following example would be executed.

#
# Rotate Example
#
src:    .byte       0x2,0x4,0x8,0x10,0x10,0x8,0x4,0x2
dst:    .byte       0,0,0,0,0,0,0,0

rot:    addr   src,r0    #point to the source character
        movqd  1,r1      #the source warp is one
        addr   rottab,r4 #point to the ROTIMG table
        ROTIMG           #rotate the character
        movd   r2,dst    #store the dest. character low 32 bits
        movd   r3,(dst+4)#store the high 32 bits
#
# The character has been rotated and stored.  
#
